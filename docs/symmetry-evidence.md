# Symmetry evidence

Use **Compare > Symmetry evidence** in the viewer or desktop app to fit a reflection plane to a mesh or point cloud and verify the finished CAD against that plane. Choose the approximate plane normal and separate numerical thresholds for reference p95 and maximum sampled CAD deviation. The fitted plane is visible in the scene; evidence reports both sides separately, with trimmed-face and trim-edge statistics. A reference that fits poorly is marked for review independently of CAD symmetry.

The fit uses the attached reference's saved alignment, in the shared part frame in millimetres. A point-only PLY or PLY.GZ can be selected directly in the panel, with explicit source units; its original bytes are preserved under `scans/`. This point-cloud input does not replace the ordinary comparison target. Its points use the same current reference alignment, or original coordinates when no target is attached. Use a saved box region to exclude out-of-scope material such as cloth when fitting the reference; the finished CAD check still covers the whole model. Component regions are not offered as fit regions because an explicit box makes the selected scan scope clear.

The fit is a bounded local least-squares reflection search near the chosen coordinate axis. The angular search uses tangent bounds inscribed in the requested angular cone, so the allowable rotation in a single tangent direction is smaller than that cone's maximum angle. It is not a global guarantee of the best symmetry plane. Mesh fitting uses point-to-plane residuals, then independent holdout samples measured against the triangle surface. Point-cloud fitting uses nearest points, whose spacing contributes to measured error. Both sides need evidence; search limits and poor reference fit remain visible. Existing scan defects, region crop boundaries, and asymmetric details can bias the result. Rotate a badly oriented reference with the existing alignment controls before fitting.

CAD verification samples every finished edge and the interior of every trimmed face. The face classifier excludes UV samples inside holes. Reflected points are measured against a compound of the finished faces, rather than against a solid: a solid distance can return zero for points inside material and hide an unpaired hole. The CAD result is `within_sampled_threshold` only when the largest measured distance is at most the requested CAD tolerance. The result includes edge spacing, face sample setting, sample count and separate negative/positive/on-plane statistics. A finite sampling pass is not an all-point proof of mathematical symmetry; narrow faces without samples produce an actionable unknown result instead of a pass. Reference-plane fitting and alignment error also contribute to these CAD distances.

Saved semantic locations are checked separately. In **Named inspection regions > Functional feature and local sections**, enter an optional **CAD center X Y Z (mm)** and **Symmetry pair group**. `center_mm` is an explicit authored location in the part frame; legacy `point_mm` is accepted as an alias and normalized on save. Existing `reference_point_mm` annotations stay in the original reference frame and are transformed by the saved alignment. CAD centers and reference annotations form distinct categories with CAD and reference thresholds respectively. Pairing is one-to-one across the fitted plane within `symmetry_group`, falling back to the feature role. A point on the plane pairs with itself. Missing counterparts and shifted counterparts are deviations; features with neither location stay in `unlocated_features`. Region boxes never imply a feature center. These annotations do not prove that an actual hole or other feature exists at the given center in the B-rep.

Finished periodic faces also report their seam curves independently in `cad.periodic_seams`. The check identifies OCCT seam edges on U/V-periodic faces, samples them under the same total CAD budget, and matches reflected curves one-to-one to seams of compatible surface/periodicity types. Every category includes count, matched/unmatched count, threshold, negative/positive/on-plane errors, individual records, and a category identity derived from the full evidence identity. Periodic face counts, periodic directions and seam sample counts remain explicit. Faces that are periodic but whose trims do not contain a seam are listed and have no seam-curve measurements. A zero-count category is `not_assessed`, never a pass.

Periodic seams are parameterization topology and need not be material boundaries: rotating a cylindrical seam can produce a seam deviation while the physical CAD remains symmetric. The seam category therefore does not change the physical boundary verdict. Finite seam samples do not prove matching B-spline control points, knot multiplicities or continuity across a periodic boundary. Authored feature locations and sampled seams extend the evidence; neither replaces local sections and fit checks.

**Preview reference plane on axis** composes the fitted-plane correction with the current alignment. It moves only the reference preview, never the CAD or original scan. Use the normal **Apply alignment** action to save it, then verify again. Do not use the pre-alignment report as evidence for the newly aligned state.

```sh
nurb symmetry light_seal --axis x --reference-tolerance 0.3 --cad-tolerance 0.01 --json --output build/light-seal-symmetry.json
nurb symmetry light_seal --against scans/cloud.ply.gz --units mm --axis x --json
nurb symmetry light_seal --check-report build/light-seal-symmetry.json --json
```

Repeat the original options when checking a saved report. The identity records finished B-rep geometry, reference content and units, alignment, full current parameters and variant, source revision, fit region every saved semantic location/group, and every numerical setting. Each category expires with its parent identity, including on center/group edits; unsaved feature-editor edits also hide the viewer results. Version 1 reports expire because they did not include these categories. Source revision hashes project Python, card, TOML, JSON and local analytic CAD inputs; hidden directories and generated `build/` output are excluded. JSON explicitly tagged `symmetry_evidence` or `local-section-evidence` is excluded so writing a report cannot invalidate itself. This deliberately conservative revision can expire evidence after unrelated project source edits. Reports written by the viewer have the same default-configuration identity as the CLI. `--check-report` compares that identity without running the expensive reflection measurements again.

In the viewer, rebuilding or changing alignment/thresholds removes the displayed numbers and fitted plane until another check. The saved JSON retains its measured inputs for audit; use the CLI current/stale check before relying on it later. A disconnected client can recover the last in-memory report on reconnect through the normal part sync. Evidence is not persisted silently into a card.

## Jobs and limits

The viewer sends `target_symmetry` with `name` and `options`, optionally `cloud={filename,data,units}` for a base64 PLY upload or `reference_file` for a previously uploaded file in `scans/`. Responses have `type=target_symmetry`, part `name`, geometry `token`, and per-run `request_id`. States are `running`, `measured`, `unknown`, `cancelled`, or `stale`. A measured result carries `kind=symmetry_evidence`, `schema_version=2`, `identity`, `source_revision`, `configuration`, `alignment`, `options`, `plane`, `cad` and `feature_centers`. Send `target_symmetry_cancel` with the same part token and request ID to cancel. Failures and changed inputs return no distances. At most two jobs run concurrently, and only one per part.

One deadline covers snapshot preparation, initial B-rep copy, reference loading, identity hashing, serialization, reference fitting, trimmed-CAD distances, statistics and final identity validation. The default is 30 seconds; `--timeout` accepts up to 120 seconds. The live shape is inherited into a disposable snapshot child, which is reaped before a fresh interpreter performs the measurements. Timeout or cancellation kills and reaps the currently owned child, including during a blocking kernel query. CLI builds also run inside this deadline; initial live preview builds remain in-process.

`--memory-limit` and viewer `memory_limit_mb` set the child RSS limit in MiB, default 2048. macOS and Linux sample resident memory every 50 ms; exceeded limits return `unknown` with reason `memory_limit`, without distances. Inherited resident pages count, and short allocation overshoots between samples remain possible. Unsupported platforms explicitly refuse bounded verification. `resources` records the enforcement policy, peak observed RSS, phase, timeout and child identities; it does not claim an allocator-level hard limit. The independent CAD sample budget rejects oversized work rather than truncating evidence. Point-cloud fitting is limited to 500,000 selected points; uploads are limited to 48 MiB and PLY.GZ expansion to 256 MiB.

No live display triangulation or cached comparison is replaced. A new request retains a previously measured report separately as `last_symmetry`; the running or failed request never inherits its distances. Progress names preparation, fitting, sampling and distance phases without inventing a percentage. Model or reference changes still invalidate completion and retained evidence must be checked against its recorded identity.

## Desktop and integration

The controls live in the comparison tool panel and remain visible under `?embed`; no sidebar/footer dependency is introduced. The desktop shell does not duplicate these numerical inspection results, so `desktop/src` needs no new rail fields or postMessages. The feature uses only vendored viewer resources and existing scientific dependencies, and works offline.

The implementation reuses `feature_evidence.shape_identity` and `evidence_identity`. Its isolated `symmetry_service` owns background jobs; `server.py` adds only initialization and command dispatch. The viewer adds an independent panel and one comparison-refresh and websocket-response hook, so it can integrate alongside feature sections and precise mesh verification without changing their measurements or caches.

## Before and after fitting

Evidence includes a `plane.baseline` measured around the chosen coordinate axis through the reference bounding-box center before fitting, plus `plane.after_fit`. Both use exactly the same independent validation samples and distance query, with per-side counts and residual statistics. `plane.p95_improvement_mm` is the literal baseline p95 minus fitted p95; negative values are retained when fitting makes holdout error worse. The viewer displays both values and the signed change. This compares reflection-plane fits, not scan-to-CAD registration accuracy or a guarantee that applying the preview will improve CAD agreement.

**Save evidence JSON** uses the shared desktop-safe artifact bridge. In the app, the server writes a uniquely named file under `build/evidence-exports/` and the existing `nurb:saved` shell message reveals it. Browser users receive a normal download. Saved inspection recipes under `inspections/` are excluded from source revision hashing, alongside generated build output.
