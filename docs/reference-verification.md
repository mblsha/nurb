# Reference verification

The live comparison reuses the displayed mesh so editing remains responsive. Its policy is **Display mesh estimate**: absolute accuracy in millimetres is unknown, even when a relative display setting has a small numeric value. Use **Absolute mesh verification** before assessing a small mating lip, recess, or dovetail. The comparison panel's verification action uses the same policy as the CLI.

```bash
nurb compare bracket --mesh-accuracy 0.02 --feature-size 0.3 --mesh-timeout 30 --memory-limit 2048 --json
```

`--tolerance` is the acceptable surface deviation. `--mesh-accuracy` is the requested absolute OCCT deflection in millimetres, defaulting to the smaller of 0.025 mm and one quarter of the acceptance tolerance. `--feature-size` states the smallest feature being assessed. The result warns when deflection exceeds one fifth of that feature or one quarter of the acceptance tolerance. It also warns when feature size is unspecified. These ratios are screening rules, not evidence that a feature exists or was reconstructed correctly.

Verification owns one end-to-end deadline, starting before snapshot preparation and including B-rep copying and serialization, reference loading and hashing, meshing, every distance/statistics phase, and final identity checks. The default is 30 seconds; `--mesh-timeout` accepts up to 120 seconds. A disposable snapshot child inherits the live B-rep without copying it in the server; after it is reaped, a fresh interpreter performs geometry computations. This avoids inherited OCCT worker-pool locks. The inherited snapshot can still encounter a native lock; if it stalls, timeout or cancellation kills and reaps it and reports unknown. Watchdog polling and child cleanup add a small amount of wall time beyond the requested work budget. CLI model building is inside its job deadline too. Initial live preview builds and other CAD operations remain in the main modeling process.

`--memory-limit` sets the child resident-memory limit in MiB, default 2048. macOS and Linux are monitored every 50 ms; crossing the limit stops and reaps the child and yields `unknown` with reason `memory_limit`. The monitor includes inherited resident pages and allows brief allocation overshoot between samples; it is not a hard allocator ceiling. Other platforms refuse this verification path with `unsupported_platform`, with no unbounded fallback. Separately, `--mesh-triangles` limits accepted output to one million triangles by default, or at most five million. A triangle limit is not a memory budget. Timeouts, memory limits, failed CAD faces and exceeded triangle limits produce no comparison numbers and never trigger a coarse fallback.

Results report requested absolute deflection, triangle count, feature-size ratio, policy warnings, and `measured_error_bound_mm: null`. OCCT's requested deflection is not an independently measured error bound. Distances and coverage are sampled, and the source scan's own uncertainty remains separate. A result called `measured` means the requested computation completed, not that the interface has passed physical fit testing.

The viewer's verification job returns immediately and leaves the build lock free while meshing. Progress identifies preparation and measurement phases without inventing a percentage. Results carry the build token, displayed shape identity, source and card identities, and reference stamp. A changed model, source dependency, reference, transform, tolerance, or region invalidates completion. New requests retain the last valid verification separately in `target.last_verification`, while the current request remains visibly running, unknown or cancelled. The cached live comparison is unchanged. A retained report is never substituted for a failed request; model/reference changes still invalidate evidence.

Static assembly clearance failures remain distinct from measured collisions. If OCCT cannot intersect a declared pair or measure its distance, its finding says **Clearance unknown**, identifies both components, and carries `measurements.status = "unknown"`. It provides no fabricated zero distance or overlap. The check fails because verification is incomplete. Valid empty intersections still mean no overlap.

## Viewer protocol

Send `target_verify` with `name` and optional `accuracy_mm`, `feature_size_mm`, `timeout_s`, `max_triangles`, and `memory_limit_mb`. Responses use `target_verification`, a build `token`, and a per-request `request_id`. States are `queued`, `running`, `cancelling`, `cancelled`, `measured`, `unknown`, or `stale`; `phase` describes progress. Only `measured` includes `metrics`. Failed or superseded results contain `error`. `target.verification` persists the latest result separately from the cached live `target.metrics` estimate. The viewer displays this panel in embedded desktop mode too; the desktop rail does not duplicate numerical comparison results.

Send `target_verify_cancel` with the same `name`, `token`, and `request_id` to stop an active request. A matching request first reports `cancelling`; the child is killed and reaped, then the job reports `cancelled` with no metrics. Tokens from earlier requests cannot cancel a later job. Cancellation terminates the current child even inside a blocking snapshot, kernel or distance query. Responses include `resources` with deadline scope, current phase, RSS policy, peak observed RSS and owned child PIDs. Successful CLI JSON also includes these resources. Explicit failure reasons distinguish timeout, memory limit, cancellation, stale inputs and worker failure.
