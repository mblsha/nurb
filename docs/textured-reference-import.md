# Textured PLY reference import

Choose a PLY with its declared PNG/JPEG image beside it, a compressed `.ply.gz` with the same image sidecar, or a ZIP containing exactly one PLY/PLY.GZ and its assets. The PLY must name its image with `comment TextureFile relative/path.png`. ZIP paths and texture paths must stay inside the bundle; absolute paths, parent traversal, symlinks, encrypted entries, duplicate case-insensitive paths, missing textures, multiple PLY meshes and multiple TextureFile declarations fail explicitly. No source file is executed and no external image URL is fetched. A file with images but no TextureFile declaration is ambiguous and needs an explicit declaration before import.

The shared viewer's Compare → Add reference picker accepts a ZIP or a PLY plus its image files selected together. Flat sidecars work directly in the picker; use a ZIP to preserve nested image paths. Desktop New from mesh accepts the same mesh/CAD formats, automatically finds a declared PLY image inside its source directory, and uses the same engine import path. Confirm the original units before creating or attaching the reference. Analytic STEP/B-rep inputs use millimetres.

```sh
nurb import scan.zip --preview --units mm
nurb import scan.ply.gz --units mm --exclude-component component-2
nurb new housing --from scan.zip --units mm
nurb new housing --from scan.zip --units mm --exclude-component component-2
nurb scan scan.zip --units mm --json
```

`nurb import --preview` reports bounds, connected-component IDs, original units, scale to mm, source SHA256, per-asset SHA256 and texture identity without writing files. Without `--preview`, explicit `--units` is required and the command prints the portable derived reference path plus its manifest. The new-part command makes the usual editable bounding-box draft; it does not reconstruct the model or infer which components are noise.

Imports live under `scans/import-<source identity>/`: `original/` preserves the selected source bytes, `assets/` preserves the exact PLY and image bytes, and each selection has a self-contained `reference-<policy identity>.glb` plus `.import.json` provenance. The derived GLB uses millimetres; its reference-unit control is fixed to mm. To correct the original unit choice, reimport using the Replacement file units picker or the CLI. The manifest records original units and scaling, source and texture hashes, connected-component bounds and triangle counts, selected exclusions and the output hash. Existing assets are never overwritten with different bytes. Source hash verification is required before generating another selection. Retain the whole import directory when moving a project.

Texture display and measurement use separate meshes. Import splits vertices at per-face UV seams and exports that display mesh without position welding, preserving its image mapping. Measurement copies may weld vertices by position so a UV seam is not misreported as an open surface. Component detection also welds a separate topology copy; a texture seam alone is not a detached component. No decimation, smoothing, centering or guessed alignment is applied.

Open Compare → Source assets and detached components to inspect provenance and preview the original connected pieces. Check or uncheck components while looking at the textured reference, then choose Save selected components. Measurements continue to refer to the saved selection until that action; saving produces a new derived GLB, preserves the rigid alignment and named regions, and rebuilds comparison so old evidence expires. Cancel preview restores the saved reference. All source components are included by default, and every saved exclusion remains reversible by previewing the preserved source again.

Limits: a ZIP has at most 128 entries and 256 MiB of expanded assets; a compressed PLY expands to at most 256 MiB; a texture has at most 32 million pixels. Viewer uploads total at most 48 MiB; larger supported references can be imported locally with the CLI or desktop project picker. PNG/JPEG atlases and triangulated PLY with face `texcoord` or vertex UV properties are supported. Point-only PLY, multiple atlases, arbitrary UV/material sidecar conventions and encrypted ZIPs are not supported. At most 256 component groups are presented; if more exist, the smallest remaining fragments form one explicitly labelled group. Component selection is manual and does not certify that a small piece is noise.

Pillow is an explicit MIT-CMU dependency because trimesh's PLY and GLB texture paths require its optional image codec and otherwise silently lose the image. It validates image dimensions/format and embeds local textures. The source distribution declares it and the lockfile pins it; desktop staging includes it in the hash-pinned dependency lock used during first-launch provisioning. Like existing Python dependencies, initial provisioning downloads it, while subsequent imports and viewing work offline. Pillow's license is available in the desktop About panel; its installed wheel retains the notices for bundled codecs. The browser still uses the existing local Three.js loader and adds no network dependency.
